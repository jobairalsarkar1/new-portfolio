## My Specialty (What I'm Best At)

### Backend Systems & Architecture
This is where I thrive. I design and build APIs that don't break under pressure. I think about database schemas, data flow, performance, and how systems handle growth. Whether it's building a REST API, a type-safe tRPC layer, or a Kafka pipeline that syncs data in real-time—I know how to approach it.

At FringeCore_, I worked on a Hospital Information System handling patient data, appointments, and billing. We built real-time data pipelines using Kafka to migrate from Oracle to PostgreSQL without disrupting operations. That kind of work taught me what "production-grade" actually means.

### Modern Frontend Development
I build user interfaces that work. React, Next.js, responsive design with Tailwind CSS—I understand component architecture, state management, and how to create interfaces that are both functional and pleasant to use. I've built dashboards, marketplaces, real-time UIs, and admin tools.

### Full Stack Integration
I don't just build backend systems in isolation or frontend interfaces without context. I connect them cohesively. I understand how React components talk to APIs, how authentication flows work end-to-end, and how to structure a codebase so that frontend and backend engineers can work together without stepping on each other's toes.

### Monorepo Architecture & Type Safety
I organize code in ways that scale. Using TypeScript across frontend and backend means I catch errors early. Tools like tRPC let me build APIs where the frontend automatically knows what the backend can do—no more guessing, no more breaking changes.

### Real-Time Features
I've built systems that update in real-time. Live dashboards, instant notifications, synchronized data across users. I know the difference between WebSockets, Server-Sent Events, and polling, and when to use each one.

### Data Pipelines & Migrations
I've done legacy-to-modern migrations. Oracle to PostgreSQL. Monolithic to modular. I understand data consistency, CDC (Change Data Capture), and how to move data at scale without losing anything or disrupting the business.
